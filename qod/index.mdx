**Starlake Quack on Demand** (QoD) is a multi-tenant [Arrow Flight SQL](https://arrow.apache.org/docs/format/FlightSql.html) gateway for [DuckDB](https://duckdb.org) and [DuckLake](https://ducklake.select): a single, governed, horizontally-scaled SQL endpoint in front of many DuckDB engines, with per-tenant isolation, fine-grained ACLs, federated queries, and ODBC/JDBC/ADBC access.

Like [Starflow](/), QoD is Apache-2.0, runs entirely on your own infrastructure, and phones home to no one.

## QoD and Starflow

QoD is a standalone product; you do not need Starflow to run it. If you use Starflow, the [`starlake quack`](/cli/quack) command can host a Quack DuckDB server inside the Starflow JVM for local, single-node use, and Starflow can query any Flight SQL endpoint, including a QoD fleet, as a [regular connection](/guides/project-setup/connections). For multi-tenant fleets with autoscaling and ACLs, use QoD.
